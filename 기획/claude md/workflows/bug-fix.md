# Workflow: 버그 수정 (`bug-fix`)

## 목적

보고된 결함의 원인을 파악하고 안전하게 수정하며, 재발을 막기 위한 지식과 문서를 남긴다.

## 자동 선택 트리거

- "버그", "오류", "에러", "크래시", "동작을 안 해요", "예외가 발생해요"
- 스택 트레이스/에러 로그가 함께 제공된 요청

## 공통 절차

[WORKFLOWS.md](WORKFLOWS.md)의 공통 1~5단계(CLAUDE.md/구조/docs/KnowledgeBase 확인,
필요시 update-docs)를 먼저 수행한다.

## Agent 실행 순서

| 순서 | Agent | 목적 | 실행 방식 |
|---|---|---|---|
| 1 | `architecture` | 버그 발생 영역의 구조/의존성 파악 | architecture, knowledge와 병렬 |
| 1 | `knowledge` | 관련 모듈의 과거 이력/설계 의도 확인 | architecture와 병렬 |
| 2 | `coding` | 원인 분석 및 수정 구현 (필요 시 architecture에 재확인) | 순차 |
| 3 | `testing` | 재현 시나리오로 회귀 검증 | 순차 |
| 4 | `documentation` | 변경 사항 문서 반영 | 순차 |

## 완료 후 절차

- 관련 문서 갱신: `docs/Architecture.md`(구조 변경 시), `docs/Todo.md`(재발 방지 후속 조치)
- `docs/KnowledgeBase.md` 갱신: 근본 원인과 수정 방식을 기록 (삭제 금지, 병합)
- 결과 요약: 원인 → 수정 내용 → 검증 결과 → 남은 리스크 순으로 보고

## 산출물

- 수정된 소스 코드
- 회귀 테스트(가능한 경우)
- 갱신된 관련 문서

## 주의사항

- 증상만 없애는 임시방편이 아니라 근본 원인을 수정한다. 근본 원인 파악이 불확실하면
  그 사실을 명시하고 임시 조치임을 알린다.
- 수정 범위를 버그와 무관한 코드로 확장하지 않는다.

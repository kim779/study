# Workflow: 테스트 (`testing`)

## 목적

테스트 전략을 수립하고 시나리오/코드를 작성하여 품질을 검증한다.

## 자동 선택 트리거

- "테스트 작성해줘", "테스트 커버리지 확인", "검증해줘", "메모리 누수 확인해줘"

## 공통 절차

[WORKFLOWS.md](WORKFLOWS.md)의 공통 1~5단계를 먼저 수행한다.

## Agent 실행 순서

| 순서 | Agent | 목적 | 실행 방식 |
|---|---|---|---|
| 1 | `testing` | 테스트 전략 수립, 시나리오/코드 작성, 가능하면 실행 | 순차 |
| 2 | `coding` | 테스트에서 발견된 결함 수정 (조건부: 결함 발견 시에만) | 선택적 |
| 3 | `documentation` | 커버리지 갭/후속 조치를 Todo.md에 반영 | 순차 |

## 완료 후 절차

- 관련 문서 갱신: `docs/Todo.md` (남은 테스트 커버리지 갭)
- `docs/KnowledgeBase.md` 갱신: 테스트로 드러난 동작 특이사항 기록
- 결과 요약: 작성/실행된 테스트 → 결과(성공/실패/실행불가) → 남은 갭

## 산출물

- 테스트 코드 또는 시나리오 문서 (`test/` 하위)
- 갱신된 `docs/Todo.md`

## 주의사항

- 실행이 불가능한 환경에서는 "실행하지 못했다"는 사실을 명확히 보고한다.
- 결함 수정은 `coding` Agent가 담당하며, 수정 후 반드시 재검증한다.

# source-index

## 목적

프로젝트의 모든 소스 파일을 한눈에 찾아볼 수 있도록 파일 단위 색인을 만든다.

## 입력

- 프로젝트 루트 경로
- `*.cpp`, `*.c`, `*.h`, `*.hpp` 파일 목록

## 수행 절차

1. 공통 사전 점검
   1. `CLAUDE.md` 읽기
   2. `docs/` 폴더 확인, `docs/SourceIndex.md`가 있으면 먼저 읽는다.
   3. 기존 색인 내용을 최대한 재사용하고 삭제하지 않는다.
   4. 가능하면 이전 색인 생성 이후 변경된 파일만 재분석한다 (git diff 또는 mtime 비교).
2. 각 파일마다 다음 정보를 기록한다.
   - 파일명(경로)
   - 역할 (한두 문장 요약 — 파일 상단 주석/네임스페이스/클래스 구성으로 추정)
   - 주요 클래스
   - 주요 함수
   - 관련 파일 (같은 클래스의 헤더/구현 짝, 강하게 include되는 파일)
   - 사용 API (WinAPI, COM, MFC, STL 등 주요 카테고리)
   - 의존 모듈 (링크되는 DLL/LIB 또는 상위 모듈)
3. 파일이 많을 경우 디렉토리/모듈 단위로 섹션을 나누어 표로 정리한다.
4. 기존 `SourceIndex.md`와 비교하여 변경된 파일의 행만 갱신하고, 삭제된 파일이 아니라면
   기존 행을 유지한다. 실제로 삭제된 파일은 "삭제됨" 표시 후 별도 섹션으로 이동한다 (완전 제거 금지).

## 출력

- `docs/SourceIndex.md` (파일별 표 형식)

## 주의사항

- 역할 요약은 코드 근거(클래스명, 함수명, 주석)에 기반하여 작성하고 추측이면 명시한다.
- 파일 수가 많은 프로젝트는 모듈/디렉토리 단위로 섹션을 나누어 가독성을 유지한다.
- 기존 색인 행을 임의로 삭제하지 않는다.

# knowledge-base

## 목적

프로젝트 작업 중 얻은 지식(코드로는 드러나지 않는 설계 의도, 과거 이슈 원인, 도메인 규칙 등)을
`KnowledgeBase.md`에 지속적으로 축적하여 이후 작업의 맥락으로 재사용한다.

## 입력

- 새로 기록할 지식 항목 (사용자가 직접 제공하거나, 다른 Skill 실행 중 발견된 사실)

## 수행 절차

1. 공통 사전 점검
   1. `CLAUDE.md` 읽기
   2. `docs/` 폴더 확인, `docs/KnowledgeBase.md`가 있으면 먼저 전체를 읽는다.
   3. 기존 항목을 삭제하지 않는다.
2. 새 지식 항목을 주제별 섹션(예: "빌드", "동시성", "레거시 이슈", "외부 SDK 특이사항")으로 분류한다.
   기존에 해당 섹션이 있으면 그 아래에 추가하고, 없으면 새 섹션을 만든다.
3. 기존 항목과 내용이 겹치거나 같은 주제를 다루면 **병합**한다 (중복 문장을 나열하지 않고
   하나로 합치되 정보 손실이 없도록 한다).
4. 각 항목에는 가능하면 근거(파일 경로, 날짜, 관련 이슈)를 함께 남긴다.
5. 상충하는 새 정보가 들어오면 기존 항목을 삭제하지 말고, 최신 정보를 위에 추가하며
   이전 정보는 "(과거 기록, 최신 정보로 대체됨)"으로 표시한다.

## 출력

- `docs/KnowledgeBase.md` (누적 갱신)

## 주의사항

- 어떤 경우에도 기존 항목을 삭제하지 않는다. 대체가 필요하면 "과거 기록"으로 표시만 한다.
- 중복 내용은 반드시 병합하여 문서가 무한히 길어지지 않도록 한다.
- 코드만 읽으면 알 수 있는 내용(구조, 시그니처 등)은 여기 넣지 않는다 — 그런 내용은
  Architecture.md/SourceIndex.md 등 해당 문서로 보낸다. 이 문서는 코드에서 바로 드러나지
  않는 지식 전용이다.

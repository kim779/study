# HTS 고도화 요구사항 — 현행 HTS(ibks/AXIS) 갭 분석

RFP 요구사항([프로젝트.md](프로젝트.md))을 현재 HTS 코드/문서와 대조한 결과. 작성일 2026-09-20.

## 읽는 법 / 신뢰도 주의

- 판정: ✅ 충족 · 🟡 부분(있으나 요건에 미달하거나 범위가 좁음) · ❌ 없음/불가 · ❓ 코드만으로 판단 불가(서버·타 시스템·정책 영역 또는 미확인)
- **근거의 수준**: 코드를 정독한 것이 아니라 (1) 파일/프로젝트 구조, (2) 키워드 검색, (3) 기존 분석문서(`ibks/docs`, `AXIS/docs`)를 대조했다. 기존 문서 중 "추정" 표기된 부분은 그대로 "추정"으로 옮겼다.
- 맵 소스(`map_src`, 16,774개 파일) 검색은 **맵 본문에 그 문자열이 있는지**만 본다. 화면명이 별도 메뉴 테이블에 있으면 잡히지 않으므로, 맵에서 **못 찾은 것은 "없다"의 근거가 약하다**. 반대로 찾은 것도 "그 문자열을 포함한 맵 수"이지 동작 검증은 아니다.
- 서버(전문/시세/주문 처리)와 별도 관리자 시스템은 이 저장소에 없다. 그쪽 요건은 ❓로 두었다.

## 현행 HTS 구조 요약 (판정의 전제)

- **AXIS** (`src/AXIS`): 호스트 EXE. MFC MDI, VS2019(v142), C++17, **Win32(x86) 전용**, MFC 동적 링크. `MainFrm.cpp` 34,924줄(God class).
- **axWizard** (`src/ibks/Wizard`): `.map` 화면을 해석해 그리는 화면 런타임 OCX. 소켓 프로토콜 `_axisH`, 스크립트 엔진(VBScript + 신규 Python 3.11).
- **화면 = 맵 + 스크립트**: 화면 16,774개 맵 파일(`map_src/IB`). 컨트롤은 `CONTROL/` 아래 OCX 108개 프로젝트, 별도 EXE/DLL 성격 화면은 `APPL/` 71개.
- **외부 모듈**: AhnLab SafeTx(ASTx), INCA(nProtect), Xecure(암호화), 공동인증(CertifyCtrl), WebView2, cpprestsdk, IBKSConnector(OPEN API).

## 우선순위별 갭 요약

**A. 구조적 갭 (크고 전면 영향)**
1. **64bit 전환(1-10, 8-3)** — 모든 프로젝트가 Win32. 정적 링크된 32bit 보안 라이브러리와 OCX 108개가 동시에 걸림. 제안 견적과 일정에서 가장 큰 변수.
2. **시세 처리/UI 스레드 구조(1-3, 8-2)** — "멈춤 없음"과 "처리량 측정" 요건에 직접 대응하려면 수신·파싱·화면 갱신 분리가 필요.
3. **시장/제도 하드코딩(2-3)** — NXT 도입 과정에서 시장구분 로직이 분산됨. RFP가 명시적으로 지양하라고 한 항목.

4. **통합검색(4-2)** — 화면/메뉴/뉴스/공시/상품 통합.
5. **사용자 환경 서버 저장(1-5)** — 현재 로컬 저장.
6. **인포맥스 ASP 해외 시세 연계(5-2)**.
7. **성능 측정 체계(8-1)**, **OSS/라이선스 대장(10-2)**.

## 2차 조사로 확정된 사항 (2026-09-20)

1차에서 ❓였던 항목 중 코드로 확인 가능한 것을 조사해 반영했다. 판정 변화: 1-7, 1-12, 3-3이 ❓→🟡.

- **화면 저장·복원은 이미 있다(1-4)**: 종료 시 `save_laststat`, 시작 시 `createUserScreen`. 위치/크기/최대화/연동 그룹/종목까지 저장. 남은 문제는 로컬 저장이라는 점과 모니터 구성 변경 보정이 없다는 점.
- **화면 간 연동은 그룹 방식(1-7)**: 그룹이 같은 화면끼리 종목코드(`1301`)를 공유.
- **고객/직원 구분은 런타임 플래그(1-12)**: 포트(15201/15101)와 `CertLogin` 분기. 분리 빌드가 아님.
- **자동 재연결 없음(3-3)**: 서버 지시(`0x99`)로 재로그인하는 경로만 있음.
- **정정**: 1차 문서에서 `0x96`을 "긴급공지 수신"으로 적었으나, 실제로는 서버가 파일 목록을 내려 강제 다운로드시키는 경로다(3-4에 반영). 텍스트 긴급공지 표시 경로는 별도.
- **발견**: `NOENC.TXT`가 컴파일 스위치 없이 동작(7-2), 개인정보 마스킹 코드 없음(7-4), 직원 계정 해시 하드코딩(1-12). 세 건 모두 보안 점검 관점에서 제안서·감리 대응 시 알고 있어야 한다.
